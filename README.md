# Контроль ловушек — Telegram Mini App для дезинсекторов

Менеджер создаёт **заявку (сделку) в amoCRM** и назначает техника. Техник видит её в Telegram, едет на объект, сканирует **QR-коды на ловушках**, отмечает состояние каждой и **закрывает заявку** — сделка в amoCRM сама переходит в «Выполнено» и получает примечание с итогами и ссылкой на печатный акт.

## Дизайн: InsectProtect × Nothing

- Монохромные карточки на точечной сетке. Тема: главная → Инструменты → **Светлая / Тёмная / Как в Telegram** (по умолчанию тёмная, выбор сохраняется в профиле).
- Фирменный оранжевый InsectProtect `#F58220` — только для главного: основная кнопка (чёрный текст на оранжевом), счётчики, активные элементы.
- Шрифты (Google Fonts): **Inter** — текст и заголовки капсом, **JetBrains Mono** — цифры (часы, счётчики, KPI, PIN) и подписи капсом.
- Виджет на главной: сколько осталось до следующей заявки (за час до начала — зелёным); если заявок со временем нет — виджет скрыт.
- Токены цветов — CSS-переменные в `web/src/index.css`, базовые компоненты — `web/src/components/ui.tsx`.

## Аккаунты и доступ

- Вход — через Telegram. **Первый, кто откроет приложение, становится администратором** (или те, кто указан в `ADMIN_TG_IDS`).
- **Приглашение:** Админ-панель → Сотрудники → «Пригласить сотрудника» → имя и роль → ссылка `t.me/<бот>?startapp=inv_…`. Сотрудник открывает её и сразу получает доступ. Ссылка одноразовая, действует 7 дней. Для работы ссылки в @BotFather должен быть включён **Main App** с адресом сервиса.
- Без приглашения новый сотрудник отправляет заявку (ФИО, телефон), администратор подтверждает её в «Сотрудниках».
- **PIN-код:** при первом входе каждый задаёт 4 цифры, дальше PIN спрашивается при каждом открытии приложения и после 5 минут в фоне. 5 ошибок — блокировка на 15 минут. Забытый PIN сбрасывает администратор.
- **Права техника:** видит только свои выезды; не может печатать QR-этикетки (только администратор); не может открыть или скачать PDF-акт, выгрузку, базу клиентов, админ-панель; может удалить только свой незавершённый выезд.
- **Права администратора:** всё, включая исправление и удаление актов.

## Админ-панель

**Вкладки настраиваются:** Настройки → «Вкладки админ-панели». Снимите галочку, и вкладка пропадёт из строки сверху. Стрелками ↑↓ меняется порядок. «Обзор» и «Настройки» есть всегда. Настройка своя у каждого администратора. Полосы прокрутки под вкладками нет, строка листается пальцем, колесом или тачпадом.

- **Обзор:** выезды за 7/30/90 дней, завершённые, в работе, замечания и фото, высокая заселённость, объекты без подготовки, график по дням, разбивка по специалистам, обработкам и вредителям, список «Требуют внимания».
- **Заявки:** сколько заявок пришло за период, выполнено (и % от всех), открыто сейчас (новые / в работе), просрочено, отменено, среднее время закрытия, график новых заявок по дням, выполнение по каждому специалисту, вредители в заявках, список просроченных.
- **Вредители:** доля каждого вредителя в выполненных актах, количество объектов, случаи высокой заселённости, динамика за 6 месяцев, разбивка по обработкам, активность в ловушках, повторные объекты (2+ выезда с вредителями за период).
- **KPI:** помесячная история по каждому сотруднику за 12 месяцев: получено заявок, выполнено, % в срок (акт закрыт не позже даты заявки), опоздания, отменено, всего актов (с выездами без заявки), замечания офиса, среднее время выполнения. Рейтинг за выбранный месяц, график по месяцам, выгрузка в Excel (CSV). Сотрудник видит свою историю: главная → «История по месяцам».
- **Акты:** поиск (юрлицо, адрес, специалист, № акта), фильтры по статусу, обработке, специалисту; выгрузка в Excel (CSV).
- **Замечания:** отправить замечание сотруднику, счётчик замечаний по сотрудникам за месяц, список с отметкой «прочитано», удаление ошибочного замечания.
- **Сотрудники:** приглашения, заявки, роли, блокировка, сброс PIN.
- **Журнал:** кто и когда удалил или исправил акт, изменил сотрудника, сделал выгрузку, загрузил базу.
- **Настройки:** чат офиса, база клиентов, **обнулить счётчик отменённых заявок** за неделю / месяц (убирает их из списка «Отменённые» и счётчика на дашборде; история KPI сохраняется).

### Уведомления и замечания от офиса

- На главной у сотрудника есть 🔔 с красным счётчиком непрочитанных. В панели: замечания офиса, новые, изменённые и отменённые заявки, возвраты акта на исправление. Фильтр «Замечания».
- Под заголовком у сотрудника плитки за текущий месяц: **Выполнено** (завершённые акты), **Ожидают** (открытые заявки) и **Замечания**.
- **1-го числа каждого месяца** панель, счётчик выполненных и счётчик замечаний начинаются с нуля. История при этом не удаляется: акты, заявки и журнал остаются в базе и в дашбордах.
- Как отправить замечание:
  1. **Ответить (reply) на PDF-акт в чате офиса** — текст ответа станет замечанием автору акта, бот подтвердит «📌 Замечание отправлено».
  2. Кнопка «Замечание технику» в открытом акте.
  3. Админ-панель → вкладка «Замечания».
- Сотрудник получает замечание в приложении и сообщением от бота в личку (если он нажимал /start у бота).

### Исправление и удаление актов

- **Исправить:** акт возвращается в работу (ред. 1, 2…), после сохранения в чат офиса уходит новый PDF с пометкой «Исправленный акт — предыдущая версия недействительна».
- **Удалить:** с указанием причины; если акт уже был в офисе, туда приходит сообщение «Акт № … удалён». Всё фиксируется в журнале.

## Выезд без заявки

1. **Кто клиент:** Юрлицо или Физлицо.
   - Юрлицо — поиск по базе / новый клиент с Cod fiscal, юр. адресом и представителем → адрес объекта.
   - Физлицо — ФИО, телефон, адрес. В акте: «Persoană fizică · ФИО», представитель — ФИО.
2. Тип обработки → **вредители** → **тип помещения**; для квартиры/дома — **количество комнат** (1–6+, попадает в акт как «Квартира / дом, 2 комнаты»). Причина («клиент позвонил напрямую»).
3. **Подтверждение администратором** (если выезд создаёт не админ): админам в Telegram приходит «🟠 Выезд без заявки — нужно подтверждение» с кнопками ✅ / ❌; то же — в приложении на экране выезда. Пока не подтверждено, работать с выездом нельзя (сервер блокирует изменения), у выезда метка «Ждёт подтверждения». После одобрения **создаётся заявка** (номер, запись в теме техника «🟠 Выезд без заявки · подтвердил …», учёт в KPI), технику приходит уведомление, выезд открывается. Выезды, созданные админом, не требуют подтверждения — заявка создаётся сразу.

## Выезд

1. Юрлицо → адрес → **тип обработки**: дезинсекция, дератизация или дезинфекция (список меняется переменной `PROCEDURES`).
2. **Дезинсекция:** обязательна «Оценка объекта» — степень заселённости (не выявлено / низкая / средняя / высокая / критическая) и подготовка помещения (выполнена / частично / не выполнена). Без неё выезд не завершить.
3. **Замечания с фото** (для любой обработки): категория (подготовка помещения, степень заражения, нет доступа, санитарное состояние, другое), до 10 фото с камеры или из галереи и комментарий. Фото сжимаются на телефоне до 1600 px.
4. **Станции мониторинга (QR):** если клиент — юрлицо, в выезде спрашивается «Нужны станции мониторинга?».
   - **Нет** — обычная обработка.
   - **Да** — сканируете QR на каждой станции. Новая станция привязывается к юрлицу и адресу: против кого (грызуны / тараканы и ползающие / летающие — моль, мухи), устройство (для грызунов — клеевая ловушка или родентицидная станция; для насекомых — клеевая, феромонная, лампа), номер и место.
   - При каждом обслуживании по станции записывается: состояние (в порядке / заменена / повреждена / отсутствует / нет доступа), **приманка погрызена** (для родентицидных: не тронута / частично / полностью), **есть ли кто-то в ловушке** (кто и сколько), заменена ли приманка/пластина, комментарий.
   - После завершения в PDF-акт добавляется **Anexa nr. 2 — электронный журнал мониторинга**: сводка, таблица результатов и история станций по последним 6 визитам (OK / MP / MT / C3 / D / L / NA). Отдельный PDF журнала — кнопка «Журнал мониторинга (PDF)» в завершённом выезде (для админа).
   - У физлиц станции работают как раньше (дератизация или если на адресе уже есть станции).
5. **Перед завершением:** выбрать, что отправить в офис — **Proces-verbal** (акт приёмки), **Anexa** (отчёт, фото, рекомендации, журнал станций), оба или ничего; при необходимости — **«Расписаться клиенту»** (клиент расписывается пальцем, подпись встаёт в поле «Beneficiar»). **Печать и подпись исполнителя** стоят в акте автоматически (Админ-панель → Настройки → «Печать и подпись»: стандартная / своя картинка / не ставить; файл по умолчанию — `server/assets/stamp.jpg`).
6. «Завершить выезд» → формируется **PDF-акт** и бот отправляет его в чат офиса **одним файлом** с короткой сводкой в подписи. В PDF: реквизиты, оценка, вредители, замечания с фото, ловушки, **рекомендации заказчику** и подписи. Если отправка не удалась — кнопка «Отправить в офис» на экране выезда.

### Акт по фирменному бланку (Proces de recepție a lucrărilor)

По умолчанию PDF строится по бланку GARNET-LUX / InsectProtect на румынском:

- **Стр. 1 — Proces de recepție a lucrărilor:** логотип, № (сквозная нумерация 0001, 0002…), дата, Localitate; Prestator (реквизиты компании) и Beneficiar (Denumirea, Cod fiscal, Adresa juridică, Reprezentant, Funcția); Lucrări efectuate (услуга, помещения, м²); Produse utilizate; Declarații și obligații; Act de recepție finală; подписи.
- **Anexa nr. 1:** оценка объекта, замечания с фото, ловушки, рекомендации заказчику (RO), заключение специалиста.

Откуда берутся данные:
- реквизиты исполнителя, текст деклараций — Админ-панель → Настройки → «Реквизиты компании»;
- список препаратов для выбора — Админ-панель → Настройки → «Препараты»;
- Cod fiscal и юр. адрес заказчика — из базы клиентов (колонки «ИНН / Cod fiscal», «Юридический адрес»), представитель и должность — оттуда же, их можно поправить в выезде;
- помещения, площадь, препараты — блок «Данные для акта» на экране выезда;
- **адрес — отдельно «Город / село» (Localitate) и «Улица, дом, кв.»**. Кнопка **«Поделиться адресом»** берёт геолокацию телефона и подставляет адрес (например «mun. Chișinău» + «str. Ismail 33»), специалист правит номер дома/квартиры. Адрес ищется через **map.md**, если в Render задан `MAPMD_TOKEN` (токен выдаётся на https://map.md/api; при необходимости адрес метода — `MAPMD_REVERSE_URL`), иначе — через OpenStreetMap (бесплатно, без ключа). То же поле есть в «Выезде без заявки» (физлицо / новый адрес).

Шаблон переключается в Настройках: «Фирменный бланк (RO)» или «Современный (RU)». Логотип — `server/assets/logo.jpg`, румынские тексты — `server/src/ro.js`.

### Рекомендации заказчику

**Тип помещения** (галочки в «Оценке объекта»): квартира/дом, кухня/кафе/ресторан, пищевое производство/склад продуктов, склад, офис, магазин, гостиница/хостел, детское/медицинское учреждение, подвал/техпомещение — для каждого свои пункты «подготовка» и «после обработки» (RU и RO). Тексты — `server/src/premises.js`.

**Нельзя находиться в помещении:** подбирается автоматически по вредителям — тараканы и блохи 4–6 ч, клопы 12–24 ч, остальное 2–3 ч; техник может выбрать вручную (2–3 / 4–6 / 12–24 / 24–48 ч). В акте выделяется отдельным блоком.

Собираются автоматически из отмеченных вредителей (тараканы, клопы, муравьи, блохи, мухи, моль/кожееды, комары, клещи, мыши, крысы) и оценки объекта: подготовка к обработке, действия после неё, сроки повторной обработки. Если подготовка не выполнена или заселённость высокая — добавляется блок «Важно». Тексты редактируются в `server/src/recs.js`.

PDF собирается на сервере без внешних сервисов; шрифт Inter (лицензия OFL) лежит в `server/fonts`.

### Подключение чата офиса

1. Добавьте бота в группу офиса.
2. Администратор пишет в группе команду `/office` (если в группе есть темы — в той теме, куда должны приходить отчёты).
3. Бот отвечает «✅ Чат подключён». Готово.

Бот работает через webhook: адрес `https://<сервис>.onrender.com/api/tg/webhook` устанавливается автоматически при запуске сервера. В личке бот отвечает на `/start` кнопкой «Открыть приложение».

## Anexa nr. 1 · Declarația beneficiarului

В каждой Anexa nr. 1 над подписями печатается обязательный блок «Declarația beneficiarului»: услуги оказаны в полном объёме, претензий к качеству и количеству нет и не будет, с условиями и рекомендациями согласен, проинформирован о препаратах и времени без доступа (подставляется из акта, например «4–6 ore»), ответственность за последствия несоблюдения рекомендаций, раннего входа в помещение или скрытых аллергий — на клиенте. Текст редактируется в Админке → Настройки → «Anexa nr. 1 · Declarația beneficiarului» (каждый пункт с новой строки, `{ore}` — время без доступа). Пустое поле — используется текст по умолчанию.

## Поделиться актом с клиентом

В завершённом выезде есть кнопка **«Поделиться с клиентом»**. Клиент получает документы, выбранные при завершении (Proces-verbal / Anexa; если «никакие» — оба). Способы:
- **Показать QR-код** — клиент наводит камеру своего телефона и скачивает PDF (приложение клиенту не нужно);
- **Отправить PDF-файл** — системное меню телефона (WhatsApp, Viber, почта); появляется, если телефон это поддерживает;
- **WhatsApp клиенту** — сразу на номер из заявки, с готовым текстом на румынском и ссылкой;
- **Telegram** — выбор чата;
- **Прислать PDF мне в бот** — файл приходит специалисту в личку, дальше «Переслать» куда угодно;
- **Скопировать ссылку** — для SMS / Viber.

Ссылка `/r/act/<id>.pdf` подписана и действует 90 дней, вход не нужен. Каждая отправка пишется в журнал действий. Новых переменных на Render не требуется.

## Роли: дезинсектор, специалист, администратор

Роль выбирается в «Сотрудники» (при приглашении или в карточке сотрудника):
- **Дезинсектор** выезжает на обработки по заявкам.
- **Специалист** тоже выезжает на обработки и сверх этого получает **поручения**: «снять 10 рекламных видео», «развезти ловушки» и т. п. За каждое поручение назначается стоимость в бонусных баллах.
- **Администратор** ставит заявки и поручения. Сам не выезжает.

## Командные заявки (большой объект)

«Новая задача» → «Обработка» → отметьте **нескольких сотрудников** и выберите **ответственного**. Ответственный ведёт акт, отмечает звонок и дорогу и получает оплату наличными.
- Остальным бот пишет «👥 Вы в команде по заявке №…, ответственный — …, стоимость делится на N: по X лей». Заявка видна им в списке, в карточке написано «Вы в команде», кнопок действий у них нет.
- **Баллы:** каждый участник получает баллы объекта **полностью**. Ответственному они записываются в акте, остальным — в KPI строкой «Командный выезд (баллы объекта)». Это учитывается в рейтинге соревнования.
- **Стоимость заказа делится поровну** на всех участников. Выполнение засчитывается каждому: в «Выполнено», в выручке по сотрудникам и в KPI у каждого доля, общая выручка не дублируется. Пример: заказ 900 лей на двоих — у каждого 450 лей и полные баллы.
- Если акт исправили, аннулировали, удалили или пересчитали баллы, баллы участников обновляются автоматически.
- Состав команды меняется в карточке заявки: «+ Команда / Изменить». Ответственного меняют через «Переназначить».

## Напоминания, срок, бонус и штраф по поручениям

- **Получение.** Исполнитель получает поручение в бот с кнопкой «✅ Принял в работу». Пока он её не нажмёт, каждые 5 минут приходит «🔔 Напоминание N».
- **Проверка.** После сдачи проверяющему (сотруднику или **менеджеру**) приходит уведомление в приложение и в бот. Каждые 5 минут идёт напоминание с кнопками «Принять / На доработку», пока он не решит.
- **За 1 час до срока** исполнитель и проверяющий получают **по одному** уведомлению. Срок — это дата и время; если время не указано, срок до 18:00.
- **Бонус и штраф.**
  - При создании поручения задаётся бонус и **штраф за просрочку** (0 / −0,5 / −1 / −2 или любое число).
  - Сдал **до срока** → после «Принять» получает бонус.
  - **Не сдал к сроку** → штраф автоматически списывается в KPI («Поручение № … не сдано в срок»). Исполнитель, проверяющий и администраторы получают уведомление. Если он сдаст позже, бонус по умолчанию 0, но офис может указать баллы вручную.
  - Если перенести срок, уже списанный штраф снимается.
- **Ограничения.** Не больше 144 напоминаний подряд. Интервал меняется переменной `JOB_ALERT_MINUTES` (по умолчанию 5).

**Прочитал / принял (галочки).** В списке поручений у каждого открытого поручения видно статус, как в мессенджере:
- **✓ красным** «не прочитал · 25 мин» — ещё не открывал;
- **✓✓ серые** «прочитал · не принял» — открыл в приложении, но не нажал «Принял в работу»;
- **✓✓ зелёные** «принял».

Сверху вкладки «Поручения» появляется красный блок «Не приняли в работу» со списком, кто не прочитал или не принял. На «Обзоре» то же видно как «не приняли N».

**Файлы к поручению.** В карточке поручения есть кнопка «📎 Прикрепить файл».
- **Что можно прикрепить:** видео, фото или документ, до 50 МБ, можно сразу несколько.
- **Кто может:** исполнитель, проверяющий и офис.
- **Куда уходит файл:** проверяющему, иначе в чат офиса или администраторам, и остаётся в поручении.
- **У каждого файла:**
  - «⬇» — скачать через браузер, до 20 МБ;
  - «✈» — бот присылает файл вам в Telegram, любого размера;
  - «×» — удалить; может тот, кто загрузил, или офис.

**Бот не запущен.** Если Telegram не даёт боту написать сотруднику (он не нажимал «Старт» или заблокировал бота), ответственные получают сообщение «🤖 … не запустил бота — уведомления не доходят». Это администраторы, а также тот, кто поставил поручение, и проверяющий.
- **Как часто:** не чаще раза в 12 часов на сотрудника.
- **Где ещё видно:** в «Сотрудниках» (у имени), в выборе «Кому» и в списке поручений отметка «🤖 бот не запущен».
- **Когда пропадает:** как только сотрудник напишет боту или нажмёт «Старт».

## Проверяющий для поручений

При создании поручения в пункте «Кто принимает работу» можно выбрать **Офис**, конкретного сотрудника или **менеджера**.
- Когда исполнитель сдаёт работу, проверяющий получает сообщение с кнопками «👍 Принять / ↩️ На доработку». В приложении у него появляется раздел «Принять работу».
- После его «Принять» баллы идут в зачёт исполнителю. Офис получает сообщение для сведения и тоже может принять или вернуть поручение.

## Роль «Менеджер» (администратор с ограниченными правами)

Менеджер назначается в «Сотрудники» (это может сделать только главный администратор). В карточке сотрудника галочками отмечаются права:
- заявки (обработки);
- поручения;
- фото и видео;
- KPI, план и баллы;
- акты и отчёты;
- сотрудники (без назначения администраторов);
- настройки;
- журнал.

**Поручения и менеджеры.**
- Менеджеру тоже можно ставить поручения: он есть в списке «Кому» (в конце, с пометкой «менеджер»). На обработки менеджеров не назначают.
- Свои поручения менеджер видит на «Обзоре» в блоке «Поручения» и сдаёт так же, как специалист.
- Принять своё поручение он не может. Его принимает главный администратор, другой менеджер или назначенный проверяющий.
- Менеджер с правом «Поручения» сам ставит поручения сотрудникам и другим менеджерам через «Новая задача» → «Поручение», но не самому себе.
- Если у менеджера нет права «Заявки», форма сразу открывается на поручении.

Менеджер видит только разрешённые вкладки и виджеты. Сервер тоже проверяет права: при попытке открыть закрытый раздел придёт ответ «Нет прав: …». «Обзор» с заявками менеджер видит всегда. Назначать администраторов и менеджеров и менять права может только главный администратор.

## Соревнование 👑

- **Рейтинг по баллам месяца** складывается из выездов, командных долей, поручений, фото и видео, бонусов и штрафов.
- **Где виден:** у сотрудника — на главной (топ-3, его место и сколько баллов до первого места), у администратора — на «Обзоре».
- **Итоги 1-го числа:** лидер прошлого месяца получает **корону 👑** рядом с именем на весь месяц и **бонус в KPI** (по умолчанию +3 б). Если лидеров несколько с одинаковыми баллами, награду получают все. Остальным приходят итоги с их местом.
- **Настройки** (Настройки → «👑 Соревнование»): размер бонуса, минимум баллов для победы, видят ли рейтинг сотрудники.
- **Первые итоги:** награды выдаются начиная с месяца, в который функция появилась.

## Сначала закрыть предыдущий выезд

Пока у специалиста есть незавершённый выезд (акт открыт), он не может начать следующую заявку: нельзя нажать «Еду к клиенту», «Приступить к обработке» или «Выезд без заявки». Сервер отвечает «Сначала завершите предыдущий выезд: <адрес> (акт № …)», а в карточке заявки появляется кнопка, которая открывает этот выезд. Звонок клиенту по следующей заявке отметить можно. Выключается в Настройках → «Функции» → «Сначала закрыть предыдущий выезд».

## Подключаемые функции и настройки

Настройки → «Функции» (доступно только главному администратору): командные заявки, проверяющий для поручений, роль «Менеджер», соревнование, «сначала закрыть предыдущий выезд». Выключенная функция пропадает из интерфейса, и сервер тоже её не принимает.

Все разделы настроек **сворачиваются**: нажмите на заголовок. Какие разделы открыты, запоминается на устройстве.

## 🎮 Новый экран сотрудника: вкладки, игра, смена в эфире, входящие

У дезинсектора и специалиста внизу 4 вкладки: **Сегодня · Входящие · Лига · Профиль** (у администратора всё как раньше).

**Сегодня:** уровень и полоса опыта → карточка «Смена в эфире» → до 3 новых сообщений офиса с кнопками → квесты дня → план месяца «как босс» (сколько баллов и ≈ выездов до KPI, плана и 120%) → **«Хочу ещё заявку»** → поручения, «сейчас», заявки, выполненные.

**Опыт (XP) и уровни** — отдельно от баллов KPI, на деньги не влияет (Настройки → Функции → «Игра», можно выключить):
- звонок клиенту до времени заявки +10 (позже +5), «Еду к клиенту» +5, начал вовремя (не позже +15 мин) +15, выезд завершён +30, фото в акте +5 за фото (до +20), ответ офису («Принял / Понял / Беру») +5, час смены в эфире +10;
- квесты дня: «3 выезда сегодня» +50, «Приехать вовремя ко всем» +30, «Фото в каждом акте» +20;
- уровни: 100 · 300 · 600 · 1000 · 1500 · 2100 · 2800… XP (Новичок → Помощник → Специалист → Профи → Мастер → Эксперт → Легенда); серия дней «вовремя»;
- значки: Первый выезд, Пунктуальный (5 дней вовремя), Воскресный, Фотограф (50 фото), Мастер клопов (20 выездов), Сотня, В эфире (40 ч), Оператор (5 видео), Чемпион.
Каждое начисление записывается один раз (таблица `xp_events`), повторные нажатия опыт не дают.

**Смена в эфире (геопозиция боту):** сотрудник в чате с ботом включает 📎 → Геопозиция → «Транслировать» → 8 часов. Бот благодарит, и за каждый час в эфире в рабочие часы (по умолчанию 8:00–20:00, до 8 ч в день) начисляет +10 XP с сообщением. Час засчитывается, только если точки приходили. Утром (8:00) бот напоминает включить смену тем, у кого сегодня заявки. Бот сам включить трансляцию не может — это ограничение Telegram. Настройки: Админка → Настройки → «📍 Смена в эфире». Функция выключается в «Функциях».
- **В пути:** в карточке заявки после «Еду к клиенту» — карта (OpenStreetMap), где сотрудник и клиент, ≈ минуты и прибытие (по прямой × 1,35, в городе ~25 км/ч), «успеваете / опаздываете», кнопка «Навигатор» (Google Maps). Адрес клиента ищется по OpenStreetMap один раз и запоминается.
- **Удалённость:** при начале выезда, если есть свежая точка из смены, удалённость (Кишинёв / до 100 км / дальше) подтверждается сама.
- **Офис:** на «Обзоре» блок «Кто где» — карта и список: едет (≈ минут), на объекте, свободен, **опаздывает** (красным, сверху).

**Входящие от офиса:** всё, что требует реакции, в одном месте — новые заявки («Принял»), переносы/отмены/замечания и прочие сообщения («Понял»), поручения («Беру»), объявления («Понятно»), вызов в офис («Иду»). Вкладки «Новые / В работе / Готово»; в работе — заявки с отметками «принял · позвонил · выехал · начал». Когда приходит новое, поверх экрана выезжает окно с кнопкой действия (+5 XP), «Открыть» и «Позже».

**Путь заявки:** в карточке заявки, выезде и завершении — дорожка «Звонок → В пути → Работа → Акт → Оплата». После «Завершить выезд» — экран награды: баллы и как они посчитаны, опыт, уровень, квесты, план месяца и кнопка «Хочу ещё заявку».

**Лига:** соревнование месяца, план с отметками KPI / план / 120%, значки и таблица «как получить опыт». **Профиль:** уровень, месяц (выполнено, баллы, замечания), план KPI, видео/фото, последний опыт, уведомления, история KPI, бот, тема, выход, версия.

**«Хочу ещё заявку»** — сообщение в чат офиса: кто просит, сколько заявок сегодня и где он сейчас (ссылка на карту). Не чаще раза в 30 минут.

## 🕵️ Контроль баллов (бот)

Настройки → «Контроль баллов» (право «KPI»). Включено по умолчанию. После каждого завершённого выезда бот сравнивает акт с заявкой и ищет признаки завышения баллов:
- акт закрыт быстрее минимума (по умолчанию 10 мин; отмечается, если без фото);
- тип помещения выше, чем в заявке (только если это даёт больше баллов), комнат или соток больше, чем указал офис;
- добавлен вредитель с большим коэффициентом (клопы к тараканам);
- выезд начат в «повышенный» день/время (воскресенье, окно, период), а заявка была на другое время;
- вечерняя надбавка, хотя заявка была дневной (на 2+ часа раньше начала вечера);
- второй акт по тому же адресу за сутки; больше N выездов без заявки за день (по умолчанию 3).

Бот считает, сколько баллов ≈ сверх заявки, и сообщает администраторам **сразу** (кнопки «✅ Всё в порядке» и «📄 Акт (PDF)») или **итогом дня** в заданный час. На «Обзоре» — блок «Контроль баллов»: неразобранные акты с причинами, кнопки «В порядке» / «Нарушение», нажатие открывает акт (баллы исправляются там вручную). Блок «Систематически» показывает сотрудников, у кого ≥30% актов с замечаниями (минимум 3) или выезды вдвое короче, чем обычно у команды. Кнопка «Проверить акты этого месяца» проверяет уже закрытые акты (без рассылки). Сотрудник об этих проверках ничего не получает, баллы автоматически не меняются.

## 📦 Большие файлы (видео и файлы поручений)

Без настроек файлы идут через Telegram: до 50 МБ на файл, в приложении смотреть можно до 20 МБ (ограничения Telegram для ботов).
Если подключить хранилище (Cloudflare R2 или любое S3), телефон загружает файл **напрямую в хранилище** — до `MAX_UPLOAD_MB` (по умолчанию 2 ГБ) на файл, смотреть и скачивать можно любой размер.

- Можно выбрать **сразу несколько** видео/фото или файлов — они загружаются по очереди, у каждого свой прогресс; не загрузившиеся можно повторить.
- **Каждый файл — отдельная запись и отдельная оценка**: в чат офиса приходит отдельное сообщение со своими кнопками «👍 Хорошее» / «👎 Без баллов», на «Обзоре» и во вкладке «Фото/видео» — отдельная карточка.
- Файлы до 45 МБ дополнительно отправляются в Telegram «как есть» (с превью), большие — сообщением с кнопкой «▶️ Открыть».
- Брошенные загрузки (связь пропала, приложение закрыли) удаляются через 12 часов.

**Подключение Cloudflare R2:** 1) dash.cloudflare.com → R2 → Create bucket (например, `insectprotect-files`); 2) R2 → Manage API tokens → Create token с правом *Object Read & Write* на этот бакет — скопируйте Access Key ID, Secret Access Key и endpoint `https://<account_id>.r2.cloudflarestorage.com`; 3) в настройках бакета → CORS policy вставьте:
```json
[{ "AllowedOrigins": ["*"], "AllowedMethods": ["PUT", "GET", "HEAD"], "AllowedHeaders": ["*"], "ExposeHeaders": ["ETag"], "MaxAgeSeconds": 3600 }]
```
4) в Render → Environment добавьте `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` (и при желании `MAX_UPLOAD_MB`). Бакет остаётся приватным — файлы открываются только по подписанным ссылкам на 1 час.

## 💵 Оплата при завершении выезда

В окне «Завершить выезд» сотрудник обязательно отмечает оплату (без этого выезд не закроется):
- **Наличные получены** — и сумму (подставляется цена из заявки, можно исправить);
- **Перечисление** — юрлицо, офис выставит счёт (выбрано заранее, если клиент — юрлицо);
- **Оплаты нет** — повтор по гарантии (можно написать комментарий, например номер акта);
- **Несколько дней** — многодневная обработка, оплата в последний день (выбрано заранее для этапа «1/2», «2/3»…; в последний день отмечают наличные или перечисление).

Где видно: в сообщении в чат офиса и в теме заявки («💵 Наличные получены: 450 лей»), в карточке завершённого выезда, в «Выполнено» — у каждого сотрудника «💵 на руках N лей» и счётчики по видам оплаты за период. У командной заявки наличные записываются на ответственного. Исправленный акт сохраняет прежнюю оплату, если её не меняли.

## «Кто заберёт» — задача для категории сотрудников

В «Новой задаче» (и для обработки, и для поручения) есть переключатель **«Конкретным / 🙋 Кто заберёт»**:
- выберите категорию: **Все / Дезинсекторы / Специалисты** (для поручений ещё **Менеджеры**);
- у обработки можно задать **бонус тому, кто заберёт** (+0,5 / 1 / 2 или любое число) — начисляется в KPI после завершения выезда (правило «claim»); у поручения награда — его стоимость в баллах после приёмки;
- всем из категории бот присылает сообщение с кнопкой **«🙋 Забрать»**, в приложении — блок «🙋 Свободные задачи» на главной;
- первый нажавший становится исполнителем; у остальных сообщение меняется на «забрал(а) Имя», офису/автору приходит уведомление;
- в админке видно: «🙋 Ждут, кто заберёт», а после — «Забрал(а) Имя · время» в карточке заявки/поручения.

## 📣 Объявления

Кнопка **«Объявление»** рядом с «Новая задача» на «Обзоре» (владелец и менеджеры с правом «Поручения» или «Заявки»):
- заголовок, текст, **цвет** (🟠 инфо, 🟣 коэффициент, 🔴 важно, 🟢 хорошее), кому (все сотрудники / дезинсекторы / специалисты / менеджеры / все, включая админов) и «показывать до»;
- быстрые шаблоны: «Собрание», «В воскресенье повышенный коэффициент», «Выходной день»;
- сотрудники получают сообщение в боте (кнопка «👍 Понятно») и цветной баннер на главной, пока не нажмут «Понятно»;
- на «Обзоре» блок «Объявления»: прочитали N из M и список, кто не прочитал; объявление можно удалить.

## Задачи: обработка или поручение

- **Сообщение в чате офиса или в теме сотрудника** — это всегда **обработка** (заявка), как раньше.
- **Админ-панель → «Новая задача»** (кнопка сверху на «Обзоре», а также на вкладке «Поручения»):
  - **Обработка**: сотрудник, адрес, клиент, телефон, дата и время, вид обработки, вредители, комнаты, этап, цена и комментарий. Заявка приходит сотруднику так же, как из чата: напоминания, «Уведомлен», «Скоро заявка». Копия уходит в его тему, если тема привязана, иначе в чат офиса. Там есть кнопка «Отменить заявку».
  - **Поручение**: один или несколько сотрудников (каждому ставится своё), текст задачи, подробности, количество (например, 10), срок и бонус в баллах (+0,5 / 1 / 2 / 3 / 5 или любое число).
- **Как сотрудник выполняет поручение:**
  - получает сообщение бота с кнопкой «✅ Принял в работу»;
  - на главной видит блок «Поручения»;
  - в карточке поручения отмечает «Сделано N из 10», пишет отчёт (например, ссылку на файлы) и нажимает **«Сдать задачу»**.
  - В день срока в 9:00 бот напоминает, если поручение ещё не сдано. Если срок прошёл, бот повторяет напоминание раз в день, а в приложении поручение помечается «Просрочено».
- **Проверка:**
  - сданное поручение приходит в чат офиса (или администраторам в личку) с кнопками «👍 Принять +N б» и «↩️ На доработку»;
  - в приложении то же самое есть на «Обзоре» → «Поручения» и на вкладке **«Поручения»** (фильтры «В работе», «На проверке», «Закрытые» и по сотрудникам). Там же при принятии можно изменить количество баллов, написать комментарий, изменить или отменить поручение.
  - Принятые баллы сразу идут в KPI как бонус с отметкой «Поручение № …».
  - «Переоценить» снимает начисленные баллы и снова открывает поручение.

## Администратор не выезжает

Администраторы и менеджеры только добавляют и подтверждают заявки — выездов у них нет:
- в `/tech` в списке только специалисты; привязать тему к администратору нельзя (и автопривязка по названию темы администраторов не выбирает);
- если тема по старой настройке привязана к администратору, заявка не создаётся — бот просит перепривязать тему через `/tech`;
- в приложении у администратора нет кнопок «Новый выезд / Выезд без заявки», шагов «Позвонил / Еду к клиенту» и «Приступить к обработке» — заявку он видит, может отменить; сервер это тоже запрещает.

## «Выполнено» по сотрудникам (администратор)

На главном экране администратора блок **«Выполнено»**: переключатель «Этот месяц / Прошлый / Всё время», строка «Все сотрудники» и строка на каждого специалиста — количество завершённых актов, сумма по заявкам (лей) и доля от всех. Нажмите на сотрудника — ниже появятся только его акты; повторное нажатие снимает выбор. Подробная статистика — Админка → KPI.

## Ошибочно выполненная заявка — аннулирование

- **Специалист** в завершённом выезде нажимает «Выполнено по ошибке — аннулировать», пишет причину → администраторам в бот приходит запрос с кнопками «🗑 Аннулировать / ↩️ Оставить»; в приложении у администратора — блок «Аннулировать выполнение?» на главном экране. Запрос отправляется один раз.
- **Администратор** аннулирует сразу из экрана выезда.
- После аннулирования акт удаляется, заявка получает статус «аннулирована» и не попадает в «Выполнено», историю и KPI сотрудника (и в сумму по заявкам). В тему заявки и в чат офиса (если акт туда уходил) приходит сообщение, в журнале действий — запись, специалист получает уведомление.
- «Нажал „Приступить“ по ошибке» (до выполнения) — отдельная кнопка на экране выезда, возвращает заявку в список.

## Баллы сотрудникам

В каждом выезде блок **«Объект · баллы»**: категория объекта (Квартира, Дом, Поликлиника S/M, Больница S/M/XL, Ресторан / кафе, Другое), для квартиры — удалённость (Кишинёв / до 100 км / дальше 100 км). Без категории выезд не завершить. Категория подставляется сама: «Квартира / дом, N комнат» → Квартира, кухня/ресторан → Ресторан; «Кишинёв» — если он есть в адресе.

| Категория | Баллы |
|---|---|
| Квартира · Кишинёв / до 100 км / дальше | 1 / 2 / 2,5 |
| Дом | 1 |
| Поликлиника S / M | 1 / 2 |
| Больница S / M / XL | 1,5 / 2,5 / 5 |
| Ресторан / кафе | 2 |
| Другое | 1 |
| Работа после 20:00 (начало или конец выезда, до 6:00 утра) | +0,5 |

Баллы фиксируются при завершении и видны: у специалиста — плитка «Баллы» за месяц, в истории и KPI; у администратора — в «Выполнено» по сотрудникам, в KPI и в CSV (колонка «Баллы»). **Редактор баллов** — Админка → «План KPI» → «Редактор баллов» (или Настройки → «Баллы сотрудникам»): переименовать, добавить или удалить категорию, задать баллы, включить «зависит от удалённости» (Кишинёв / до 100 км / дальше) для любой категории, надбавку за вечер и её час. Изменения действуют на новые выезды. В завершённом акте администратор может исправить баллы: пересчитать по другой категории или поставить вручную с причиной (специалист получит уведомление, в журнале — запись).

**Тип помещения в заявке из админ-панели.** В форме «Новая задача» → «Обработка» есть поле «Тип помещения (для баллов)»: Квартира, Дом, Поликлиника, Больница, Ресторан и т. д. У квартиры и других категорий с удалённостью ещё выбирается «Кишинёв / до 100 км / дальше». Ниже показан прогноз баллов с учётом коэффициента (например, «Квартира: 2 × 2,5 (воскресенье) = 5 б»). Тип виден сотруднику в карточке заявки и в сообщении бота (🏠). Когда он начинает обработку, тип и удалённость подставляются в акт; при необходимости их можно поменять там.

**Удалённость только по геолокации (защита от обмана).** Удалённость «до 100 км» и «дальше» засчитывается, только если она подтверждена:
- В блоке «Объект · баллы» есть кнопка **«Поделиться геолокацией»**. По координатам телефона считается расстояние от центра Кишинёва: до 15 км — «Кишинёв», до 100 км — «До 100 км», дальше — «Дальше». Удалённость ставится автоматически.
- Если нажать «До 100 км» или «Дальше» без геолокации, приложение само запросит геолокацию.
- Выбрать удалённость больше, чем показала геолокация, нельзя (сервер тоже это проверяет).
- Если удалённость указал офис в заявке, она засчитывается без геолокации.
- Без подтверждения выезд с «до 100 км / дальше» не завершить. Можно выбрать «Кишинёв».
- Расстояние видно в расшифровке баллов («Квартира · До 100 км (📍 41,6 км): 2»). Администратору в акте доступна ссылка «Карта».
- Необязательные переменные Render: `CITY_RADIUS_KM` (15), `NEAR_LIMIT_KM` (100), `GEO_CENTER_LAT` / `GEO_CENTER_LON` (центр Кишинёва).

**Надбавка за размер объекта (комнаты и сотки).** Настраивается в Настройках → «Баллы сотрудникам» → «📐 Надбавка за размер объекта»: сколько комнат и соток включено в базу и сколько баллов добавлять за каждую следующую. Если поле пустое или 0, надбавки нет.
- Пример: включена 1 комната, +0,2 за каждую следующую. Квартира на 3 комнаты = 1 + 0,4 = 1,4 б.
- **Где указываются:** комнаты и сотки задаются в заявке («Новая задача» → поля «Комнат» и «Соток»; в чате — «3 1/2 4300» или «10 соток»). Специалист может поправить их в акте, в блоке «Объект · баллы».
- **Как считается:** надбавка прибавляется до коэффициентов: (категория + вечер + размер) × вредитель × повышенный коэффициент.

**Коэффициент за вредителя.** Баллы объекта умножаются на коэффициент вредителя, отмеченного в акте. По умолчанию: тараканы ×1 (квартира — 1 б), клопы ×1,2 (квартира — 1,2 б), остальные ×1.
- Если в акте несколько вредителей, берётся наибольший коэффициент.
- Редактируется в Настройках → «Баллы сотрудникам» → «🐞 Коэффициент за вредителя». Пустое поле означает ×1.
- Формула: (категория + вечер) × коэффициент вредителя × повышенный коэффициент (воскресенье и т. д.).
- Коэффициент виден в расшифровке баллов («Квартира · Кишинёв: 1 · Клопы ×1,2») и в прогнозе при создании заявки.

**Пересчитать баллы за месяц.** Если поменяли баллы за объекты, вредителей, удалённость или коэффициенты, нажмите Настройки → «Баллы сотрудникам» → внизу «🔄 Пересчитать баллы за месяц».
1. Выберите этот или прошлый месяц.
2. Нажмите «Проверить, что изменится»: появится список актов «было → станет» и общая сумма.
3. Нажмите «Пересчитать».

Акты с баллами, исправленными вручную, не трогаются. В командных выездах баллы участников тоже обновляются. В журнал пишется запись.

### Повышенный коэффициент (фиолетовый)

Баллы за выезд (категория + вечер) умножаются на коэффициент. Если совпало несколько, берётся наибольший:
- **День недели**: по умолчанию **воскресенье ×2,5**, остальные дни ×1. Считается по дате начала обработки. Меняется в редакторе баллов, в блоке «⚡ Повышенный коэффициент по дням недели».
- **Особые периоды**: там же, «Добавить период» — название, даты «с/по», коэффициент (например, «Пасха ×2»).
- **По дням и часам**: там же, «Добавить время» — дни недели, время «с–до» и коэффициент, например **суббота 14:00–24:00 ×1,5**. «До» 24:00 — до полуночи; если «до» раньше «с» (22:00–06:00), окно идёт через полночь. Считается по дате и времени начала обработки (для заявки — по плановому времени).
- **Вручную для заявки**:
  - при создании в админ-панели («Новая задача» → «Обработка» → «Повышенный коэффициент»: Нет / ×1,5 / ×2 / ×2,5 / ×3);
  - в чате — строкой вида `x2`, `×2,5`, `коэф 2`;
  - в карточке заявки: администратор нажимает «Повысить». Сотрудник получает уведомление; если выезд уже начат или завершён, коэффициент и баллы пересчитываются.
- **Вручную для завершённого выезда**: «Баллы» → «Повышенный коэффициент (вручную)».

Такие заявки и выезды **выделяются фиолетовым**: полоса слева, фиолетовая иконка и метка «⚡ ×2,5». В карточке заявки есть фиолетовый блок с причиной («Воскресенье», название периода или «назначен офисом»). В акте фиолетовыми становятся метка под адресом и блок баллов, а в расшифровке баллов написано, например, «×2,5 (воскресенье)».

**Поздравление в боте.** Когда у сотрудника появляется заявка с повышенным коэффициентом, бот один раз присылает ему поздравление: «🎉 Поздравляем! У вас заявка с повышенным коэффициентом ×2,5 (воскресенье) — баллы за неё умножатся», с номером, адресом и датой. Такое бывает, когда заявку создали, подтвердили, перенесли на воскресенье или в особый период, исправили в чате или офис повысил коэффициент. Повторов нет: одна заявка — одно поздравление, даже если коэффициент потом меняли. При переназначении заявки поздравление получит новый исполнитель.

## Напоминание «Скоро заявка»

За **30 минут** до времени заявки специалисту в бот приходит «⏰ Заявка через N мин» с кнопкой **«👀 Увидел»**. Пока он не нажмёт — сообщение повторяется **каждые 2 минуты** (старое удаляется, новое приходит со звуком), максимум 30 раз. Напоминания прекращаются также, если специалист нажал «Еду к клиенту» или начал обработку. Если время заявки перенесли — напоминания начнутся заново под новое время.

Переменные (необязательно): `SOON_MINUTES` (30), `SOON_EVERY_MINUTES` (2), `SOON_MAX` (30). На бесплатном Render сервис должен не засыпать (см. keep-alive), иначе напоминания не уйдут.

## План KPI (Админка → «План KPI»)

**Переменные (Админка → План KPI → Настройки KPI):**

| Переменная | По умолчанию | Смысл |
|---|---|---|
| Базовый план | 60 баллов | план при коэффициенте сезона 1,0 |
| Сезонные коэффициенты | янв 0,6 · фев 0,6 · мар 0,8 · апр 1,0 · май 1,2 · июн 1,4 · июл 1,5 · авг 1,5 · сен 1,2 · окт 1,0 · ноя 0,8 · дек 0,6 | план месяца = база × коэффициент |
| Веса итога | план 70 · в срок 20 · качество 10 | сумма 100 |
| Норма «в срок» | 90% | при 90% и выше часть «в срок» = 100 |
| Штраф за замечание | 25% | каждое замечание офиса −25% в части «качество» |
| Потолок | 120% | перевыполнение плана учитывается не выше 120% |
| Минимальный план | 70% | пока набрано меньше этого % плана — KPI = 0 (0 — без порога) |
| Напоминание о плане | 60 мин | повтор, пока сотрудник не нажмёт «Ознакомлен» |

**Формула:** KPI % = min(баллы / план, потолок) × вес плана + min(% в срок / норма, 1) × вес «в срок» + max(0, 100 − замечания × штраф) × вес качества.

План каждому сотруднику можно задать вручную (новичок, отпуск) — нажать на число плана; «По сезону» возвращает авто-план.

**Рассылка:** 1-го числа в 9:00 бот сам присылает каждому специалисту план с кнопкой «✅ Ознакомлен»; кто не подтвердил — повтор каждый час с 9:00 до 20:00 (до 12 раз). Кнопка «Отправить план сотрудникам» — вручную (например, после изменения плана). В таблице видно, кто ознакомился. У специалиста на главной — карточка «План KPI» с прогрессом и кнопкой «Ознакомлен с планом». При первом деплое посреди месяца план автоматически не рассылается — начнётся с 1-го числа следующего месяца (или отправьте вручную).

## Специалисты (Админка → «Специалисты») и компьютерная версия

**Специалисты** — карточка на каждого специалиста за выбранный месяц: KPI %, баллы из плана с полосой прогресса, заявок в работе, выполнено, % в срок, замечания; отметки «сейчас на выезде», «не подтвердил заявки», «просрочено», «план не подтвердил». По нажатию — подробности: контакты, сумма в леях, опоздания, отмены клиентом, переносы, график и таблица KPI за 6 месяцев (с отметкой «ознакомлен с планом»), открытые заявки и последние 25 выездов (открываются).

**Компьютер:** приложение открывается и в Telegram Desktop / Web. На широком экране главная — в две колонки (слева заявки и выезды, справа план, месяц и инструменты), админка — во всю ширину, окна открываются по центру, а не снизу.

## Быстрый акт

В открытом выезде сверху переключатель **«Полный акт / ⚡ Быстрый акт»**. В быстром режиме специалист отмечает только вредителей и категорию объекта (баллы) — оценка и данные бланка скрыты. При завершении клиент/офис получают **одну страницу «Act de executare a lucrărilor»**: исполнитель, клиент, адрес, услуга, вредители, дата, специалист, время без доступа, короткое подтверждение, печать и подпись клиента. Файл называется «Act nr … .pdf», делится так же (QR, WhatsApp, бот). Баллы и KPI считаются как обычно.

- **Замечания с фото** доступны и в быстром акте — кнопка «Добавить замечание с фото» на экране выезда, как в полном. Если есть хотя бы одно замечание, при завершении оно попадает отдельным приложением к акту (можно отключить — см. ниже).
- **Станции мониторинга**, если на объекте они уже были заведены раньше, в быстром акте видны и доступны для проверки (новый мониторинг быстрый акт не предлагает заводить). Результат проверки попадает в акт отдельным приложением — электронным журналом станций (как «Anexa nr. 2» в полном акте), если проверялась хотя бы одна станция.
- **Что приложить к акту:** при завершении, если есть замечания и/или проверенные станции, появляется выбор — включить их в итоговый PDF или нет (по умолчанию оба включены). Если ни того ни другого нет, акт остаётся как раньше — одна страница.

## Главная админ-панели, дашборды, вызов в офис

**Админ-панель — стартовый экран администратора.** На «Обзоре» сверху — доска заявок: «Ждут подтверждения» (кнопки «Подтвердить / Отменить»), запросы на аннулирование, кто не нажал «Уведомлен», все открытые заявки по сотрудникам (раскрываются), отменённые, и кто сейчас на выезде. «Назад» ведёт на экран «Выезды» с инструментами (тема, QR-этикетки).

**Что показывать на «Обзоре»** — Админка → Настройки → «Главная страница админ-панели»: галочками включаются блоки «Заявки», «Показатели выездов», «Эффективность сотрудников», «Своевременность в приложении», «Вызовы в офис», «График по дням», «Разбивки», «Требуют внимания» (у каждого администратора — свой набор).

**Эффективность сотрудников** — KPI %, баллы / план, выполнено, в срок, замечания за текущий месяц; полоса выполнения плана с отметкой 100%.

**Своевременность работы с приложением** (7 / 30 / 90 дней): доля заявок, подтверждённых «Уведомлен» за 5 минут, среднее время реакции, сколько напоминаний понадобилось, доля «Увидел» на «Скоро заявка», доля выездов, начатых не позже 15 минут от времени заявки, подтверждение плана, подтверждение вызовов в офис; итог — среднее этих долей.

**Вызвать в офис** — Админка → Специалисты → сотрудник → «Вызвать в офис» (можно с комментарием). Сотруднику в бот приходит «🏢 Вас вызывают в офис» с кнопкой «✅ Получил»; пока не нажмёт — повтор каждые **2 минуты** (до 30 раз). В приложении у него красный баннер с той же кнопкой. Когда подтвердит — администратору приходит сообщение. Вызов можно отменить. Переменные (необязательно): `OFFICE_CALL_EVERY_MINUTES` (2), `OFFICE_CALL_MAX` (30).

## Бонусы и штрафы (Админка → План KPI → «Бонусы и штрафы»)

Бот сам предлагает **+ баллы** за хорошую работу и **− баллы** за плохую — по правилам (кнопка «Правила»: вкл/выкл, баллы, порог):

| Правило | По умолчанию |
|---|---|
| Перевыполнение плана (≥ 110%) | +3 |
| Месяц без замечаний (при ≥ 5 выполненных) | +1 |
| Отличная реакция в приложении (своевременность ≥ 95%) | +1 |
| Замечание офиса | −1 за каждое |
| Медленно подтверждает заявки (< 60% за 5 мин) | −1 |
| Опаздывает на заявки (< 70% вовремя) | −1 |
| Не подтвердил вызов в офис | −0,5 за каждый |
| Не подтвердил план KPI | −0,5 |

В **последний день месяца в 18:00** рекомендации формируются автоматически, администраторам приходит сообщение в бот. Можно и в любой момент — «Рекомендации бота сейчас». Каждую рекомендацию можно применить, отклонить или вернуть на рассмотрение; «Применить все» — одним нажатием. «Вручную» — свой бонус/штраф с причиной. Применённые баллы добавляются к баллам месяца (план, KPI, карточка специалиста), сотрудник получает сообщение «🎁 KPI за сентябрь: +3 балла — …» или «⚠️ … −1 балл — …».

## Типы замечаний и штрафы

Админка → «Замечания» → «Новое замечание»: сотрудник, **тип замечания** и комментарий. У каждого типа — сколько баллов снимается в KPI текущего месяца (сразу, без подтверждения):

| Тип | Штраф |
|---|---|
| Неопрятный вид | −1 |
| Машина: грязная / неисправна | −1 |
| Опоздание к клиенту | −1 |
| Некорректное общение с клиентом | −2 |
| Жалоба клиента | −2 |
| Нарушение техники безопасности | −2 |
| Ошибки в акте / не заполнен | −0,5 |
| Другое | −1 |

«Изменить типы и штрафы» — переименовать, добавить, удалить, поменять баллы (0 — без штрафа). Сотрудник получает «⚠️ Замечание от офиса · −1 балл». Удалили замечание — баллы вернулись. Замечание без типа (или ответом на акт в чате офиса) штрафуется правилом бота «Замечание офиса (без типа)» в конце месяца. То же окно — в акте («Замечание технику»).

## Разбор недели (бот) и админ без экрана «Выезды»

**Разбор недели.** Каждый **понедельник в 10:00** бот анализирует последние 7 дней работы каждого специалиста с приложением (своевременность: «Уведомлен», «Увидел», начало выезда вовремя, вызовы в офис) и готовит сообщения: **похвалу** (своевременность ≥ 90%) или **рекомендации, что улучшить** (< 80%) с конкретными цифрами. Администраторам приходит «Разбор недели готов» с кнопкой «✅ Отправить все». **Ничего не уходит сотрудникам без подтверждения.** В админ-панели на «Обзоре» блок «Разбор недели»: текст можно поправить, «Отправить» / «Не отправлять», «Отправить все», «Разобрать неделю сейчас», история.

**Администратор:** приложение сразу открывает админ-панель, экрана «Выезды» у администратора нет. Инструменты (тема оформления, QR-этикетки, версия) — в Админке → Настройки → «Инструменты».

## Видео и фото с объектов (мотивация)

**Специалист:** на главной — карточка «Видео и фото с объектов» (сколько баллов уже получено в месяце) и кнопка **«Добавить видео / фото»**; в открытом выезде — такая же кнопка (файл привязывается к объекту). Снять или выбрать файл до **50 МБ**, подпись по желанию, загрузка с прогрессом.

**Куда уходит:** в чат офиса (или администраторам в личку, если чат не подключён) — видео/фото с подписью и кнопками **«👍 Хорошее — начислить баллы» / «👎 Без баллов»**. Файлы хранятся в Telegram, на сервере не занимают место.

**Оценка:** кнопкой в Telegram или в админ-панели → «Обзор» → «Видео и фото от специалистов» (просмотр видео/фото прямо в приложении, файлы до 20 МБ; больше — в чате). По умолчанию **+0,2 балла** за хорошее, **не больше 1 балла в месяц** на человека; при оценке количество можно изменить. «Баллы →» — изменить +за штуку и лимит месяца. Баллы идут в KPI (как бонус), специалист получает сообщение.

**Вкладка «Фото / видео» в админ-панели** — все файлы в одном месте:
- сводка: всего, на оценке, хороших, без баллов, начислено баллов;
- фильтры: статус (На оценке / Хорошие / Без баллов / Все), тип (видео / фото), месяц (все / текущий / прошлый), сотрудник;
- карточки с превью, автором, объектом и подписью; нажатие — полноэкранный просмотр;
- **«⬇ Скачать»** — файл открывается в браузере и сохраняется как `insectprotect-xxxx.mp4/jpg` (до 20 МБ);
- **«✈ В Telegram»** — бот присылает оригинал вам в личку (любой размер, можно переслать или сохранить);
- оценка: поле баллов + 👍 Начислить / 👎 Нет; после решения — **«Переоценить»** (баллы снимаются, файл снова «на оценке»).

- **Быстрый акт**: автоматически ставится заселённость «Средняя» (стандартная) и подготовка «Выполнена» (клиент подготовился).
- KPI менеджеров: плитки подписаны «План/Выручка всех менеджеров»; менеджер без выбранной схемы показывается как «Стандарт».

## KPI менеджеров, «Звонилка» и бот-коуч (v44)
Вкладка **«Продажи»** в админ-панели. Модель повторяет таблицу «KPI менеджера»:
- **План** = базовый план × сезонный коэффициент месяца (или свой план на месяц).
- **K_KPI** = Σ вес × (факт / цель), для «меньше — лучше» — цель / факт; каждый показатель не больше «макс. коэф.» (1,5).
- **K(% плана)** — ступенчатая лестница (0→0 · 60→0,5 · 80→0,75 · 90→0,9 · 100→1 · 110→1,2 · 120→1,3 · 130→1,5).
- **Премия** = выручка × ставка × K_KPI × K; ниже порога отсечки (70%) — 0; ниже критического порога — минус % от премии.
- **Итого** = оклад + премия + разовый бонус (≥130%) + супербонусы − штраф за незаполненные заявки (по умолчанию 0).
- Проверено на примере из таблицы: сентябрь, 291 903 MDL → 108%, K_KPI 0,87, K 1,0 → премия 5 306, итого 16 306.

**Откуда факты.** Автоматически: выручка — выполненные заявки, созданные менеджером (`tasks.author_id`), B2C/B2B по полю «фирма»; звонки, конверсия, сделки, абонентские и B2B договоры — из «Звонилки»; CRM — доля заявок без пропусков (или дополненных за N минут). Отток и отзывы (и свои показатели) вносит администратор во вкладке «Факты»; любое авто-значение там можно заменить, а выручку — дополнить договорами вне приложения.

**Настройка (главный администратор).** Для каждого менеджера: готовая схема (Стандарт как в таблице · Аккаунт B2B · Колл-центр B2C · Новичок), план, ставка, оклад, порог, сезонность, набор KPI с весами и целями (из каталога или свой), лестница K, бонус ≥130%, критическое недовыполнение, структура плана, супербонусы, «применить ко всем». Общие настройки: обязательные поля заявки, частота напоминаний, рабочие часы, время коуча, квесты «Звонилки». Суммы и выплаты видит только главный администратор; менеджер — только свои.

**Ошибки в заявках (v45).** В любой заявке дезинсектору всегда должны быть адрес, дата и время, телефон (набор полей настраивает администратор). Если чего-то нет — это ошибка: бот сразу пишет менеджеру и повторяет каждые 5 минут (в рабочие часы), пока заявку не исправят кнопкой «Исправить» в кабинете (`POST /api/tasks/:id/fill`) или правкой сообщения. Кому напоминать: заявку создал менеджер — ему; создал администратор или кто-то в чате — всем менеджерам; менеджеров нет — администраторам. Проверяются и заявки, созданные любым другим способом (фоновая проверка за последние 3 дня). Ошибка, не исправленная за 15 минут, снижает KPI «CRM» автора-менеджера.

**Кабинет менеджера (v45).** У менеджера вместо «Админ-панели» — «Кабинет менеджера», открывается сразу на вкладке «Мои продажи» (бонус, «Звонилка», KPI и советы, ошибки в заявках). Факты месяца и настройки KPI меняет только главный администратор.

**Бот-коуч.** Каждое утро (будни, 10:00) менеджеру: план/факт, сколько сейчас получит, отставание от темпа и сколько нужно продавать в день, 2–3 самых «дорогих» слабых KPI с советом, сколько не хватает до следующей ступени и сколько тогда получит.

**«Звонилка» (мини-игра).** Кнопка «Позвонил — записать результат» → Сделка (сумма, абонент, B2B) / Перезвонить (бот напомнит) / Отказ / Не дозвонился. XP: звонок 2, дозвон +3, сделка +25, абонент +15, B2B +10, крупная сделка +50. Квесты дня (40 звонков · 20 дозвонов · 3 сделки), комбо сделок подряд, серия рабочих дней, «Час силы» (таймер 60 минут), рекорд дня, лига менеджеров (% плана и XP, без сумм). Отмена звонка — 15 минут.

**Супербонусы (MDL, настраиваются):** личный рекорд выручки (500), крупная сделка от 10 000 (300, до 3/мес), новый абонент (100, до 10/мес), идеальная CRM (300), марафон звонков — 15 дней с квестом (300), мастер конверсии ≥50% (300). Плюс разовый бонус ≥130% плана (1 000).

Новых переменных Render не требуется.

## Заявки из тем Telegram

Офис пишет заявки прямо в группе — в теме конкретного техника, и они сразу появляются у него в приложении.

**Настройка (один раз):**
1. Сделайте бота **администратором группы** (иначе Telegram не показывает боту обычные сообщения). Право нужно только одно — читать сообщения.
2. В теме техника (например, «Заявки Артем») администратор приложения пишет `/tech` и выбирает сотрудника кнопкой.
3. Повторите для других тем. `/help` в теме — шаблон заявки.

**Как писать заявку** — любым из способов:
```
Клиент: SRL «Название»
Адрес: mun. Chișinău, str. Ismail 33
Дата: 25.09
Время: 10:00
Вредители: тараканы, клопы
Телефон: +373 69 000 000
Комментарий: вход со двора
```
или свободно: `SRL Beta, str. Ismail 33, клопы, завтра 11:00`. Бот понимает даты (25.09, завтра, послезавтра), время, вредителей (RU/RO), телефон; тип обработки определяет по вредителям.

**Комнаты · этап · цена.** Строка вида `plosnita 3 1/2 4300` читается так: 3 — комнаты, 1/2 — этап обработки (первая из двух), 4300 — цена в леях. Комнаты можно не писать (`plosnita 1/2 4300`); также понимаются `этап 1/2` и `4300 лей`. В заявке появляется строка «🧾 этап 1 из 2 · 3 комн. · 4300 лей». В акт переходят «Квартира / дом, N комнаты», тип помещения и время без доступа. Суммы по выполненным заявкам видны в KPI (колонка «Сумма» в CSV).

**Вредители — как в журнале компании:**

| В сообщении (RU / RO) | В приложении и акте |
|---|---|
| клопы · plosniță | Клопы · Ploșnițe |
| рыжие тараканы, прусак · roșcat | Рыжие тараканы · Gândaci roșcați |
| чёрные тараканы · negru, gândaci negri | Чёрные тараканы · Gândaci negri |
| летающие · zburătoare | Летающие насекомые · Insecte zburătoare |
| блохи · purici | Блохи · Purici |
| муравьи · furnici | Муравьи · Furnici |
| осы, шершни · viespe | Осы · Viespi |
| грызуны · rozătoare (мыши · șoareci, крысы · șobolani) | Грызуны → Дератизация |

Если написано просто «тараканы» / «gândaci» без цвета, будет «Тараканы». Слова-вредители вырезаются из адреса: «ул. Мира 5 клопы» → адрес «ул. Мира 5».

**В приложении у техника** заявки разложены по вкладкам **Сегодня** (плюс просроченные и без даты) · **Завтра** · **Будущие**. В «Будущих» заявки сгруппированы по дням («Пятница, 26 сентября»), внутри дня отсортированы по времени.

**Время заявки:** за час до начала время горит ярко-зелёным (с обратным отсчётом «· 25 мин»), в остальное время — оранжевым, просроченные — красным.

**Звонок клиенту (обновлено):** кнопка 📞 сразу открывает набор номера на телефоне (без сторонних страниц). Если конкретный Telegram не даёт открыть набор, появляется запасной вариант внутри Telegram: бот присылает номер в чат, нажимаете на него — звонок.

~~Старый способ:~~ зелёная кнопка 📞 прямо в строке заявки и в карточке. Android звонит сразу. На iPhone и компьютере Telegram блокирует звонки из мини-приложений, поэтому открывается страница сервиса `/r/call` в браузере Telegram, и она сразу запускает вызов (или нажмите «Позвонить» на ней). Ссылка подписана и действует 14 дней. Запасной вариант — «Отправить номер в чат с ботом» в карточке. Номера без кода (60356016, 069…) дополняются +373.

**Уведомление технику с повтором:** как только заявка создана, бот пишет технику в личку с кнопкой **«✅ Уведомлен»**. Пока он её не нажмёт, каждые 5 минут приходит новое напоминание (старое удаляется, чтобы уведомление снова всплыло со звуком). Подтвердить можно и в приложении (кнопка «Уведомлен» в карточке) или просто начав выезд. После подтверждения в теме офиса у заявки появляется «👀 … получил 10:42». Пока не подтверждено — у заявки красная метка «Не подтверждена». Настройки: `TASK_ALERT_MINUTES` (по умолчанию 5), `TASK_ALERT_MAX` (максимум напоминаний, по умолчанию 144 ≈ 12 ч).
> **Сервис не засыпает сам:** на Render он каждые 10 минут обращается к своему `/api/health` (адрес берётся из `RENDER_EXTERNAL_URL`, Render задаёт его сам — настраивать ничего не нужно). Отключить — `KEEP_ALIVE=0`, интервал — `KEEP_ALIVE_MINUTES`. Для страховки после перезапусков Render добавьте внешний пинг `https://<сервис>.onrender.com/api/health` раз в 5 минут (UptimeRobot / cron-job.org). Проверка: в ответе `/api/health` поле `keep_alive.last_ok: true`.

**Ответственный по названию темы:** тема «Заявки Артем» автоматически привязывается к сотруднику, в чьём имени есть «Артем» (ё/е не важны; техники в приоритете перед админами). Если тема была привязана к администратору, а в названии указан сотрудник — бот перепривяжет её сам и напишет об этом в теме. Вручную по-прежнему — `/tech`.

**Подтверждение заявок администратором** (Админ-панель → Настройки → «Подтверждение заявок администратором», по умолчанию включено): заявка, написанная в теме не администратором, получает статус «⏳ Ждёт подтверждения» — в теме и админам в личку приходят кнопки **✅ Подтвердить / ❌ Отменить**, на главной у админа раздел «Ждут подтверждения». Технику она уходит (с напоминаниями до «Уведомлен») только после подтверждения. Заявки, написанные самим админом, уходят сразу.

**Не подтвердили получение:** у администратора на главной счётчик заявок, которые отправлены, но дезинсектор ещё не нажал «Уведомлен» — с именем, сколько минут прошло и сколько было напоминаний.

**Перед обработкой** в карточке заявки два шага: ① **«Позвонил»** или **«Звонок не требуется»**, ② **«Еду к клиенту»** (в тему заявки уходит «🚗 … выехал к клиенту», в списке — метка «В пути»). Каждая кнопка срабатывает один раз (повторные нажатия блокируются и в приложении, и на сервере — в тему не уходит спам). Ошибочное нажатие можно отменить **один раз**: повторное нажатие «Позвонил»/«Не требуется» снимает отметку, «Еду к клиенту» — кнопкой «Отменить — нажал по ошибке» (в тему уходит «↩️ … отменено»). Кнопка **«Приступить к обработке»** активна только после обоих шагов (сервер тоже проверяет; администратору можно без шагов).

**Видимость заявок для администратора:** по умолчанию админ видит на главной только свои заявки.
 главная → Инструменты → переключатель **«Заявки всех сотрудников»**. Выключен — на главной только ваши собственные заявки; настройка сохраняется для вашего аккаунта.

**Восстановить заявку:** отменённая по ошибке заявка восстанавливается кнопкой «♻️ Восстановить заявку» под сообщением об отмене в Telegram или в приложении: главная → «Отменённые · 7 дней» → «Восстановить». Технику и офису приходит уведомление.

**Клиент просит перенести / клиент отменил** — две кнопки в карточке заявки (и в открытом выезде, пока в нём нет осмотров и фото):
- **Просит перенести:** техник выбирает новую дату (Завтра / Послезавтра / Через неделю или любую) и время, либо «клиент не назвал дату», и пишет комментарий. В тему заявки (ответом на исходное сообщение) и в чат офиса **автоматически** приходит «🔁 Клиент просит перенести заявку № …» с кнопками **«✅ Перенести на …»** и «❌ Отменить заявку». После подтверждения дата заявки меняется, технику приходит уведомление. Можно и просто исправить дату в исходном сообщении — запрос закроется. Пока офис не подтвердил, у заявки пометка «🔁 Перенос · ждёт офис».
- **Клиент отменил:** причина (передумал, другая компания, дорого, не открыл, проблема решена, другое) и комментарий. Заявка закрывается, офис получает «🚫 Клиент отменил заявку № …».
- В KPI отмены клиентом и переносы считаются отдельно и не портят показатель выполнения.

**Что происходит:**
- бот отвечает в теме карточкой заявки с кнопкой «Отменить», технику приходит уведомление в личку;
- исправили своё сообщение — заявка обновится (пока выезд не начат); ответ «отмена» на заявку — отменит её;
- техник нажимает «Начать выезд» → в теме «🚗 начал выезд»; клиент ищется в базе по названию, если нет — создаётся;
- после завершения в теме ответ на исходное сообщение: «✅ Выполнено · акт № …», PDF уходит в чат офиса.

**Заявки не приходят — как проверить:**
1. В теме отправьте `/status`. Бот ответит, привязана ли тема и видит ли он сообщения. Если бот молчит даже на `/status`, сообщения не доходят до сервера: откройте «Проверка бота», там видно состояние webhook.
2. «Тема не привязана» → отправьте `/tech` в этой теме и выберите сотрудника. Сотрудник должен хотя бы раз открыть приложение, иначе его нет в списке.
3. «Бот не администратор» → сделайте бота админом группы (права можно минимальные). Без этого Telegram присылает боту только команды.
4. Админ-панель → Настройки → «Проверка бота и тем заявок»: webhook, ошибки доставки, привязанные темы (с названиями), права бота и журнал последних сообщений с результатом разбора («заявка № 5 → Артем», «тема не привязана», «не распознано: нет адреса»).
5. Если в заявке есть вредитель, телефон или время, но нет адреса, бот ответит «⚠️ Не понял заявку». Исправьте сообщение, и заявка создастся.

## Отдельное приложение для Android (APK)

**Вход только через Telegram и только по запросу.**
1. В APK (или в обычном браузере) нажмите «Войти через Telegram».
2. Откроется бот с сообщением «🔐 Вход в приложение InsectProtect» и кнопками «✅ Войти» и «🚫 Это не я».
3. После «✅ Войти» приложение само входит и, как обычно, спрашивает PIN.

Условия и ограничения:
- Без нажатия в боте вход не выполняется. Запрос действует 10 минут.
- Войти могут только сотрудники, у которых уже есть доступ в Telegram-приложении.
- Каждый вход записывается в журнал.
- В приложении есть кнопки «Выйти» и «Выйти везде» (второй вариант выходит на всех устройствах).

**Сборка APK (автоматически на GitHub).**
1. **Адрес сервера.** В GitHub → репозиторий → Settings → Secrets and variables → Actions → Variables → **New variable**, имя `APP_URL`, значение — адрес сервиса на Render, например `https://pest-tma.onrender.com`. Вместо этого можно вписать адрес в файл `mobile/app-url.txt`.
2. **Запуск сборки.** Actions → **Android APK** → **Run workflow**. Сборка также запускается сама при изменениях в папке `mobile/`.
3. **Скачивание.** Через 5–10 минут готовый файл `InsectProtect-1.0.N.apk` появится в **Releases** репозитория. Скачайте его на телефон, откройте и разрешите установку из этого источника.
4. **Обновления.** Интерфейс APK грузится с сервера, поэтому обновления (vNN) приходят сами. Новый APK нужен только при смене иконки, названия или адреса. Он ставится поверх старого: подпись одна, `mobile/keystore`.

**Что работает в APK:**
- камера и загрузка фото и видео;
- геолокация;
- просмотр и скачивание актов и файлов (во встроенном браузере Android).

Напоминания по-прежнему приходят через Telegram-бота. APK работает только на Android.

| АО «СкладЛогистик» | 5036012345 | МО, г. Климовск, Заводская, 2 | | |

- Обязательна только колонка с названием (`Юрлицо`, `Наименование`, `Организация`, `Клиент`…), остальные — по желанию. Порядок колонок любой, шапка может быть не в первой строке.
- Несколько объектов у клиента — повторите строку с другим адресом или сделайте колонки «Адрес 1», «Адрес 2».
- Повторная загрузка не создаёт дублей: клиенты сопоставляются по ИНН, а без ИНН — по названию; новые адреса добавляются.
- Старый формат `.xls` не поддерживается — «Сохранить как» → Книга Excel (.xlsx). CSV можно в UTF-8 или Windows-1251.
- Шаблон: кнопка «Скачать шаблон» в приложении или файл `web/public/clients-template.xlsx`.
- Если клиента нет в базе, техник может добавить его прямо при создании выезда («Новый клиент»).

## Процесс с amoCRM

```
 МЕНЕДЖЕР (amoCRM)                         ТЕХНИК (Telegram)
 ─────────────────                         ─────────────────
 Сделка → компания, адрес,
 процедура, дата, ответственный
 Этап «Назначено технику»  ───────────►   «Мои заявки»: новая заявка
                                           «Начать выезд»
 Этап «В работе»  ◄────────────────────   (сделка двигается автоматически)
                                           Скан QR → осмотр каждой ловушки
                                           «Закрыть заявку» + заключение
 Этап «Выполнено»  ◄───────────────────   примечание с итогами + ссылка на акт
```

Для внеплановых работ есть кнопка «Без заявки»: техник сам выбирает юрлицо, адрес и процедуру, итоги уходят примечанием в карточку компании.

```
pestapp/
├── render.yaml        ← Blueprint для Render (Web Service + PostgreSQL)
├── package.json       ← общие команды build / start
├── server/            ← Node.js API (без фреймворков, зависимость только pg)
│   └── src/
│       ├── index.js   ← маршруты API, раздача фронтенда, печатные страницы
│       ├── amo.js     ← amoCRM API v4: поиск компаний, адреса, примечания
│       ├── auth.js    ← проверка подписи Telegram initData
│       ├── db.js      ← PostgreSQL (Render) / SQLite (локально)
│       ├── config.js  ← процедуры, типы ловушек, вредители, статусы
│       └── pages.js   ← акт выезда и лист QR-этикеток (HTML для печати)
└── web/               ← React + TypeScript + Tailwind, @telegram-apps/sdk-react
    └── src/screens/   ← Home, NewVisit, Visit, VisitSheets
```

## Как это работает

1. **Этикетки.** Главный экран → «QR-этикетки» → печать листа A4 (21 шт.). Каждая этикетка — уникальный код `PT-XXXXXX`.
2. **Выезд.** «Мои заявки» → заявка → «Начать выезд». Юрлицо, адрес и процедура берутся из сделки; если чего-то нет — техник выбирает на месте.
3. **Скан.** «Сканировать QR» открывает нативный сканер Telegram.
   - новая этикетка → указываете номер на схеме, тип и место — ловушка привязывается к адресу;
   - известная ловушка → отмечаете состояние (без активности / активность / заменена / повреждена / отсутствует / нет доступа), вредителя, количество, замену приманки;
   - кнопка «Сохранить и сканировать далее» сразу открывает сканер для следующей ловушки.
4. **Закрытие заявки.** Заключение → сделка переходит в этап «Выполнено», в неё добавляется примечание: сколько проверено, где активность, что повреждено, какие ловушки не проверены, ссылка на акт.
5. **Акт.** Печатная страница с таблицей всех ловушек — «Печать / PDF».

## Деплой: GitHub → Render

1. Создайте репозиторий на GitHub и запушьте содержимое этой папки:
   ```bash
   git init && git add . && git commit -m "Initial"
   git branch -M main
   git remote add origin https://github.com/<you>/pest-tma.git
   git push -u origin main
   ```
2. Render → **New → Blueprint** → выберите репозиторий. Render создаст Web Service `pest-tma` и базу `pest-db` по `render.yaml`.
3. Во время создания Render спросит значения переменных (см. таблицу ниже).
4. После деплоя откройте `https://<ваш-сервис>.onrender.com/api/health` — должно вернуть `{"ok":true,"db":"postgres",...}`.
5. Дальше каждый `git push` в `main` деплоится автоматически.

### Переменные окружения (Render → Environment)

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather — нужен для проверки подписи пользователя |
| `COMPANY_NAME` | нет | Название компании в шапке PDF-акта |
| `ADMIN_TG_IDS` | желательно | Telegram ID администраторов через запятую. Пусто — администратором становится первый вошедший |
| `ALLOWED_TG_IDS` | нет | Telegram ID, которые подтверждаются автоматически, без заявки |
| `OFFICE_CHAT_ID` | нет | ID чата офиса, если не хотите выбирать его в приложении |
| `PROCEDURES` | нет | Типы обработки через запятую (по умолчанию: Дезинсекция, Дератизация, Дезинфекция) |
| `ASSESS_PROCEDURES` | нет | Для каких обработок обязательна оценка объекта (по умолчанию: Дезинсекция) |
| `AMO_DOMAIN` | для amoCRM | Домен аккаунта без `https://`, например `mycompany.amocrm.ru` |
| `AMO_TOKEN` | для amoCRM | Долгосрочный токен приватной интеграции amoCRM. Без него работает своя база клиентов |
| `AMO_PIPELINE_ID` | для заявок | ID воронки, в которой менеджеры ведут заявки |
| `AMO_STATUS_ASSIGNED` | для заявок | ID этапа «Назначено технику» — такие сделки видит техник |
| `AMO_STATUS_IN_PROGRESS` | нет | ID этапа «В работе» — сделка переходит сюда при старте выезда |
| `AMO_STATUS_DONE` | для заявок | ID этапа закрытия. `142` — стандартный «Успешно реализовано» |
| `AMO_LEAD_ADDRESS_FIELD` | нет | ID поля сделки с адресом. Нет — берётся адрес компании |
| `AMO_LEAD_PROCEDURE_FIELD` | нет | ID поля сделки с процедурой (текст или список) |
| `AMO_LEAD_DATE_FIELD` | нет | ID поля сделки с датой/временем выезда |
| `TECH_MAP` | желательно | `tgId:amoUserId` через запятую — техник видит только сделки, где он ответственный. Без него все видят все назначенные заявки |
| `DATABASE_URL` | авто | Подставляется из `pest-db` |
| `REPORT_SECRET` | авто | Генерируется Render, подписывает ссылки на акты |
| `TMA_LINK` | нет | `https://t.me/<bot>/<app>` — QR будет ссылкой, открывающей приложение и обычной камерой |
| `AMO_ADDRESS_FIELD` | нет | Код или ID поля адреса компании (по умолчанию `ADDRESS`) |
| `PROCEDURES`, `TRAP_KINDS`, `PESTS` | нет | Свои справочники через запятую |
| `S3_ENDPOINT` | нет | Хранилище больших файлов, например `https://<account_id>.r2.cloudflarestorage.com` (Cloudflare R2) |
| `S3_BUCKET` | нет | Имя бакета |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | нет | Ключи API-токена бакета (права Object Read & Write) |
| `S3_REGION` | нет | По умолчанию `auto` (для R2); для AWS — регион бакета |
| `MAX_UPLOAD_MB` | нет | Максимальный размер одного файла при подключённом хранилище (по умолчанию 2048) |

Свой Telegram ID можно узнать у бота @userinfobot.

> **Бесплатный тариф Render:** сервис засыпает через 15 минут простоя (первое открытие ~30–50 сек), бесплатная PostgreSQL удаляется через 30 дней. Для работы бригады переключите сервис и базу на платные планы (Starter / Basic).

## Настройка amoCRM

1. amoCRM → **amoМаркет → ⋯ → Создать интеграцию → Внешняя интеграция**, доступы: «Доступ к данным аккаунта».
2. В созданной интеграции → вкладка **«Ключи и доступы»** → **«Долгосрочный токен»** → сгенерируйте и скопируйте в `AMO_TOKEN`.
3. В воронке заявок заведите этапы: **«Назначено технику»**, **«В работе»**, а для закрытия используйте «Успешно реализовано» (ID 142) или свой этап.
4. В сделке создайте поля (необязательно, но удобно): **«Адрес объекта»** (текст), **«Процедура»** (список со значениями как в приложении: Мониторинг ловушек, Дератизация, Дезинсекция…), **«Дата выезда»** (дата и время).
5. К сделке привязывайте **компанию** (юрлицо) — по ней ловушки и история группируются по объектам.
6. **Как узнать ID.** Задайте `AMO_DOMAIN` и `AMO_TOKEN`, дождитесь деплоя и откройте в браузере `https://<сервис>.onrender.com/api/amo/setup?key=<REPORT_SECRET>` (значение `REPORT_SECRET` видно в Render → Environment). Там все воронки с этапами, поля сделок и пользователи amoCRM с их ID — перенесите нужные в переменные.
7. Если техники не являются пользователями amoCRM (нет лицензий) — не задавайте `TECH_MAP`: менеджер просто ставит сделку в этап «Назначено технику», а ограничить круг лиц можно через `ALLOWED_TG_IDS`.

## Настройка бота в Telegram

1. @BotFather → `/newbot` → токен в `BOT_TOKEN`.
2. @BotFather → `/mybots` → бот → **Bot Settings → Menu Button** → URL `https://<ваш-сервис>.onrender.com`.
3. (необязательно) `/newapp` → создайте Mini App с тем же URL → получите ссылку `https://t.me/<bot>/<app>` для `TMA_LINK`.

## Локальный запуск

```bash
# терминал 1 — API на :3000 с тестовым пользователем и SQLite (Node 22.5+)
cd server && npm install && npm run dev
# терминал 2 — фронтенд на :5173 (проксирует /api на :3000)
cd web && npm install && npm run dev
```

Без `AMO_TOKEN` работает своя база клиентов — загрузите `web/public/clients-template.xlsx` для проверки. Вне Telegram сканер недоступен — используйте «Ввести код вручную».
